# 智能询盘模块 · 功能需求规格(v1)

> 面向 UI 设计与开发的功能规格。基于最新设计 `.claude/mockups/index.template.html`(6 模块:工作台 / **智能询盘** / 智能报价 / 客户档案 / 产品资料库 / 渠道接入)。分诊机制细节见 [channel-onboarding-requirements.md](channel-onboarding-requirements.md)。本文中的决策由产品方(本规格作者)拍定,UI 按此设计。

## 1. 定位与目标

智能询盘是产品的 **AI 询盘前台**:多渠道询盘进来后,经 AI 分诊 → 甄别评分 → 需求理解 → 自主应答/报价 → 风险护栏 → 人工接管 → 跟进成交,全链路收束在一个模块,**可见、可控、可审计**。

衡量目标:首响秒级、自动处理率↑、甄别准确率↑、人工接管率↓、不漏 A 级、不把噪音当询盘。

## 2. 角色与范围

- 角色:销售/售前(日常处理)、负责人/管理员(护栏审批、严格度设置)。
- 范围内:询盘的接入呈现、分诊、甄别、理解、应答、护栏、接管、跟进、留痕。
- 范围外(归其它模块):渠道凭证配置(渠道接入)、价格/底价规则(智能报价)、产品维护(产品资料库)、客户主档(客户档案)。本模块只**消费**它们。

## 3. 信息架构(已决策)

智能询盘采用 **两级结构**:

**一级:四个收件桶(顶部 Tab,带数字角标)**
| 桶 | 含义 | 来源 |
| --- | --- | --- |
| **收件箱** | 真实询盘(可被 AI 处理) | 分诊判定为询盘 / 干净渠道直入 / 平台通知解析 |
| **待确认** | AI 拿不准,需人工一键判定 | 分诊低置信 |
| **老客户往来** | 已知客户的在跟往来,非新线索 | 分诊命中已知客户/在跟会话 |
| **已归档** | 噪音(newsletter/通知/推销/垃圾) | 分诊判定噪音,自动归档(可搜索可恢复) |

> **决策理由**:四桶是"智能接入"的核心差异点,必须在 UI 一级呈现。绝不静默丢弃或静默自动处理——拿不准就进「待确认」,噪音进「已归档」可追溯。

**二级:收件箱内的筛选 + 搜索**
- 筛选:`全部 / A 级 / 待处理(护栏) / AI 处理中 / 已成交`
- 搜索:客户 / 公司 / 国家 / 关键词

## 4. 三个维度必须区分(避免 UI 混淆 —— 已决策)

| 维度 | 回答的问题 | 取值 | 何时产生 |
| --- | --- | --- | --- |
| **分诊类别 / 桶** | 这是不是询盘?去哪个桶? | 收件箱/待确认/老客户/已归档 | 创建询盘**之前** |
| **甄别等级** | 这个询盘有多值得跟? | A / B / C | 判定为询盘**之后** |
| **处理状态** | 这个询盘进行到哪一步? | AI 处理中/自动跟进/已甄别降级/护栏待确认/人工接管/已成交 | 处理**过程中** |

UI 上三者分别用:**Tab(桶)**、**A/B/C 角标(等级)**、**状态药丸(状态)** 表达,不可合并。

## 5. 功能需求(FR)

### FR-A 接入与归一
- A1 多渠道询盘汇入,归一为统一询盘流(渠道见「渠道接入」)。
- A2 实时询盘流:新询盘秒级出现,带 live 标识。
- A3 跨渠道同一买家合并到同一客户/会话(邮箱/电话/公司域名)。

### FR-B AI 分诊闸门(创建询盘之前 —— 核心)
- B1 嘈杂渠道(邮件/IM/平台)入站先过分诊;干净渠道(表单)直入收件箱。
- B2 分诊输出**类别 + 置信度 + 信号 + 路由**,落到四桶之一。
- B3 噪音(newsletter/自动回复/退信/内部/自动化通知/推销/垃圾)→ 已归档。
- B4 平台通知(阿里/MIC 等)→ 桥接解析为询盘进收件箱。
- B5 命中已知客户/在跟会话 → 老客户往来。
- B6 **严格度默认"宽松"**:高置信才自动建询盘,拿不准一律进待确认。可由管理员调严。*(理由:新接入期先建立信任,宁可多让人确认,也不漏不误自动处理。)*
- B7 分诊不可用(LLM 故障)时降级为规则分诊,不阻断入站。
- B8 人工在待确认/已归档的判定**反哺**黑白名单(发件人/域名),越用越准。

### FR-C 甄别与评分(Screening)
- C1 对收件箱内询盘给 A/B/C 等级 + 综合评分。
- C2 **可解释信号**必须展示:正向(企业邮箱域名、公司背调、明确规格+数量、行为信号如多次访问产品页)、负向(通用群发措辞、免费邮箱+多次群发等)。
- C3 C 级(疑似同行套价/低质)**降级**:不自动报价,保留备查,仍可人工处理。
- C4 等级可人工修正,修正计入反馈。

### FR-D 需求理解(Understand)
- D1 抽取结构化字段:产品、数量、目的地、incoterm、认证、交期、目标价、预算。
- D2 外文询盘**自动翻译为中文,保留原文**,可切换。
- D3 关联「产品资料库」做产品匹配;低置信度返回 2–3 个备选品 + 差异,不给单一武断结论。
- D4 附件(RFQ PDF/Excel)解析提取规格/数量。

### FR-E AI 自主应答与报价
- E1 AI 起草回复;A/B 级且信息充分时可自主应答(7×24、首响秒级)。
- E2 自动生成报价草稿,价格/条款/有效期来自「智能报价」(阶梯价/物流/汇率/底价)。
- E3 应答全程状态可见(AI 处理中),客户母语回复可由 AI 润色翻译。

### FR-F 风险护栏与人工接管
- F1 **底价红线校验**:报价低于软底价不可直接发送,挂起为待确认;硬底价(hard_min_price)后端硬熔断,审批也不能绕过。
- F2 触发护栏的动作(敏感承诺、大额合同、未匹配产品、PI 生成)→ 状态「护栏触发·待确认」,自动发送暂停。
- F3 人工处置三选项:**采纳 AI 建议并发送 / 修改报价(带底价校验)/ 接管会话**。
- F4 接管 ↔ 交还 AI;接管后 AI 退居草稿与润色辅助。

### FR-G 列表与会话工作区
- G1 列表项:A/B/C 角标 + 国旗 + 公司 + 标题 + 摘要 + 状态药丸 + 金额 + 未读点 + 置顶。
- G2 会话视图:对话流(甄别卡/理解卡/报价卡/护栏横幅/气泡)、顶部状态条(首响/留痕)、标记成交、打开客户档案抽屉。
- G3 空状态、加载、错误均有占位与可操作提示。

### FR-H 跟进与闭环
- H1 报价/应答后自动排到期跟进;到期提醒。
- H2 成交标记 → 状态「已成交」,沉淀成交话术。

### FR-I 留痕与合规
- I1 每步动作(分诊/评分/应答/护栏/接管/发送)留痕,可审计回溯。
- I2 AI 身份披露;租户数据隔离。

## 6. 询盘状态机(收件箱内)

`AI 自主处理中` → `自动跟进中` → `已甄别降级` → `护栏触发·待确认` → `人工接管中` → `已成交`

## 7. 给 UI 的视图清单(需要设计的界面)

1. **智能询盘主界面**:左=桶 Tab + 收件箱二级筛选 + 询盘列表;右=会话视图。
2. **待确认视图**:列表项突出"AI 判断理由 + 置信度",每项操作:`确认为询盘 / 忽略(归档) / 归到客户`;支持批量。
3. **已归档视图**:噪音列表,可搜索、可"恢复为待确认"。
4. **老客户往来视图**:按客户聚合的往来,跳转客户档案。
5. **会话视图**:甄别卡(含可解释信号)、理解卡(结构化字段 + 译文)、报价卡、护栏横幅(三动作)、修改报价弹窗(底价校验)、自动翻译开关、接管/交还、标记成交。
6. **空/加载/错误**状态。

## 8. 边界与异常
- 同一 channel_message_id 全局去重(跨"询盘"与"分诊条目"两类记录)。
- 首次接入只收"起始日期之后"的邮件,不回灌历史。
- 分诊误判由人工在待确认/已归档纠正并反哺。
- 收发能力不对称:部分渠道"只进不回"(如平台站内信)——会话视图需标明"此渠道不可自动回复,请导出/到平台回"。

## 9. 分期(MVP / P2)

**MVP(路演必须)**:四桶呈现(收件箱/待确认/已归档)+ 甄别评分(可解释信号)+ 需求理解(含自动翻译)+ AI 应答/报价 + 底价护栏与接管 + 留痕。
**P2**:老客户往来独立视图的深度聚合、平台通知桥接解析、附件深度解析、反馈学习(黑白名单自动更新→模型微调)、严格度精细化。

> 老客户往来 MVP 阶段最小实现:命中已知客户的入站归入「老客户」Tab + 跳转客户档案即可,不做复杂往来线程。

## 10. 验收标准(抽样)
- newsletter / 自动回复 / 内部邮件入站 → 落「已归档」,不生成询盘。
- "Need 1200 lamps to US" 类明确询盘 → 落「收件箱」并给出 A/B/C + 信号。
- 模糊邮件("hi can you help") → 落「待确认」,人工一键可确认升询盘。
- 报价低于底价 → 不可直接发送,挂起护栏待确认。
- 全程动作可在留痕中回溯。

## 11. 依赖
渠道接入(来源与收发能力)· 智能报价(价格/底价)· 产品资料库(匹配知识)· 客户档案(老客户/抽屉聚合)· 后端分诊服务与四桶模型(已实现:`app/services/inquiry_triage.py`、`inbound_intake.py`、`TriageItem`、`/api/v1/triage`)。
